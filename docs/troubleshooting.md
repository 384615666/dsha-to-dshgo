# DSHA 迁移 · 详细对照与排障

README 里的操作手册只讲正常流程。这里放结果状态、中断恢复、重复导入和逐条提示的完整对照。

---

## 结果状态对照

结果页里可能出现这些状态（「恢复视图」是另一个页面，见下面「中断与恢复」）：

| 结果 | 含义 | 接下来 |
|---|---|---|
| 导入完成 | 写入并读回核验全部通过 | 重启引擎，去工作区继续聊 |
| 之前已完成 | 同一备份、目标未变，重复导入被识别 | 直接去会话列表 |
| 目标会话在导入后已被修改，未自动回滚 | 导入后你又继续聊过，保护这批数据不回滚 | 保留现状，或换目标重新导入 |
| 已取消 | 你手动取消，回滚已完成 | 可以重新开始 |
| 已取消，回滚待完成 | 取消后回滚还没收尾 | 重启引擎或重选同一备份，进恢复视图处理 |
| 已取消，回滚未完成 | 回滚中断，有对象留在 pending | 同上 |
| 已回滚 | 失败后回滚完成，目标干净 | 修正问题后重新导入 |
| 回滚待完成 | 回滚开了头没收口 | 同上 |
| 失败 | 写入失败，未提交 | 按下面的提示对照处理 |

结果页本身没有回滚按钮。需要回滚时：**重启引擎**（或重新选择同一份备份）进入恢复视图，那里才有「解除遗留锁并回滚 / 回滚未完成写入 / 重新选择」。

## 中断与恢复

App 崩溃、进程被杀或断电后，重新打开面板（或重启引擎）会进恢复视图：「发现未完成或未核验的迁移任务，目标未被自动重放」，并列出 Journal 状态、未收口意图数、导入锁（空闲 / 已持有 N 秒 / 仅有 guard 残留）。

1. **先确认上次进程已经退出**，再点「解除遗留锁并回滚」；锁或 guard 还很新（默认 30 秒内）会被拒绝——那是另一个进程真的在操作。
2. 「回滚未完成写入」用于回滚开了头没收口的情况；「重新选择」只是回到首屏，**不会清掉 journal**——重新选中同一备份或重启引擎后会再次进入恢复视图。
3. 回滚只收口本批新建的对象；共享对象、以及导入后你改过的会话保持不动。
4. 只有「上次崩溃留下的锁」或「任务仍在运行」才会挡住其它导入；任务正常结束时锁已释放。恢复没收口时，同一备份会先进入恢复视图。

> ⚠️ 如果 Journal 状态是 `PLANNED`、未收口意图是 `0`（典型场景：确认计划后按了「重置」、或还没开始就崩了），**不要点**「解除遗留锁并回滚 / 回滚未完成写入」——这两个动作对「一次都没写」的已确认任务处理有已知问题（见文末「已知问题」）。

## 重复导入同一份备份

同一份备份再次选择时，面板会认出它已经导入过（提示「该备份之前已经导入过，无法重新导入」），并直接进入已确认状态；这时点「开始迁移」**只重新核验目标，不会写第二份**：

- 目标没变 → 「之前已完成」，直接去会话列表；
- 目标被改过（比如导入后继续聊过）→ 结果页显示「目标会话在导入后已被修改，未自动回滚」，**不会进恢复视图**；
- 「同 ID 但内容不同」的冲突排除只发生在**首次导入**（写入前）；重复导入不走这一步。

## 阻止原因与失败提示

| 面板提示 | 处理 |
|---|---|
| 备份中缺少被引用的附件对象 | 备份不完整，重新做一次 DSHA 一键备份 |
| 附件引用格式无效；含该会话的批次已阻止 | 取消选择该会话后重试 |
| 目标附件存储不可用，无法发布附件 | 重启引擎 / 检查目标附件库后重试 |
| 该会话已属于另一个工作区 | 同一会话不能挂两个工作区，不要重复导入 |
| 目标工作区单元不可读，无法证明成员归属 | 先修复目标工作区再导入 |
| 目标已有同 ID 但内容不同的会话，已排除 | 核对剩余集合后重新确认计划 |
| 目标已有相同会话，已排除 | 确认剩余集合后重新批准 |
| 部分旧代父会话因直属子会话证据无法闭合而被隔离 | 能导入的照常导；被隔离项见结果页 |
| N 个子会话因父会话被隔离而未导入 | 等父会话可导入后再迁这批 |
| 「失败」+「no importable sessions」 | 所有会话都不可导入：目标 preset 服务不可用或没有 Agent preset，或全部会话被附件/工作区规则排除。先在 App 里配好 preset、重启引擎后重试 |
| 备份在读取时发生变化，已拒绝混合副本 | 备份在读的时候被改动，重做备份再选 |
| 无法写入私有暂存副本 | 检查手机剩余存储；或文件已被移走，重新扫描 |
| 该目标仍有导入锁… | 见「中断与恢复」 |
| 备份超过允许的大小 | 实际很难触发（扫描会先过滤超大文件）；改用「从DSHA选择」或缩小备份 |

## 已知问题（0.1.4）

1. **确认计划后「重置」再重选同一备份**：冻结计划会留在本机；恢复视图的「解除遗留锁并回滚 / 回滚未完成写入」会把「已确认但一次都没写」的任务当成可继续的批次执行，按代码路径可能写入空会话（未在真机上复现）。遇到 Journal 状态 `PLANNED`、未收口意图 `0` 时不要点这两个按钮。
2. **目标 preset 服务不可用**时，所有会话都不可导入，面板只显示「失败」+ 英文原文「no importable sessions」，不会说明是 preset 问题。
3. 市场和 npm 安装的插件，详情里**没有**「重启内核以重载」，但面板首屏仍提示去点它——请按「重启引擎」弹窗或「立即重启」操作。
4. 重复导入被识别为「之前已完成」时，结果页仍显示「已写入目标。请重启 dsh-Go…」，实际并没有写入。
